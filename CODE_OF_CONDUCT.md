# Code of Conduct

## The short version

Be respectful. Assume good faith. Critique code, not people.

## Expected behaviour

- Be welcoming to contributors of any experience level. "This is a security
  project" is not a licence for gatekeeping.
- Give specific, actionable feedback. "This is wrong" helps nobody; "this map is
  keyed by source address and has no eviction bound, so spoofed traffic grows it
  without limit" does.
- Accept that reasonable people disagree about detection tradeoffs. A threshold
  that is too noisy in one environment is right in another.

## Unacceptable behaviour

- Harassment, personal attacks, or discriminatory language.
- Publishing others' private information.
- Using this project's issue tracker to coordinate or solicit attacks on systems
  you do not own or are not authorized to test.
- Deliberately submitting misleading security claims, fabricated detection
  results, or code presented as doing something it does not do.

That last one is a conduct issue and not merely a technical one. People deploy
defensive tools based on what they claim to do; overstating a capability can
leave someone less protected than they believe they are.

## Scope

This applies to issues, pull requests, discussions, and any other project space.

## Enforcement

Report concerns to the maintainer at gautam11652@gmail.com. Reports will be
handled discreetly. Maintainers may edit, hide, or delete contributions that
violate this policy, and may block repeat offenders.
